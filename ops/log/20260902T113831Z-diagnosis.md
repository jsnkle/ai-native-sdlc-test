**Cause.** Both failed runs are the two commits on draft PR #3, "WIP: status history", by jsnkle. The first commit adds a test to `tests/test_claims.py` that imports a function that does not exist, and the second commit only appends a comment, so it fails identically. The test itself says the feature is out of scope and does not exist yet. Every other test passes in both runs.

```
FAILED tests/test_claims.py::test_status_history_is_recorded
ImportError: cannot import name 'get_status_history' from 'app.claims'
1 failed, 43 passed
```

**Real, not flaky.** The failure is deterministic and reproduces on both commits with the same error, on the same file the commits touched. Nothing on main or on the ops branch is broken. The 2-sigma breach is an artefact of a small window: two consecutive red runs from one draft branch, plus the earlier failure on the feature branch that its fix commit already resolved, is enough to trip the four-of-five rule against a low baseline. There is no shared infrastructure or environment signal in the logs.

**Fix.** Either implement the status history lookup in the claims module and add it to the plan, or mark the test as expected-to-fail or skipped until it exists. Test-first is fine, but pushing a red test to a PR also feeds the failure rate metric. A process option is to have the detector ignore draft PRs, or weight them separately, so work-in-progress branches do not page anyone. No action is needed on main.
